# UrodLauncher: Library First and persistence test report

Updated: 2026-10-27. Branch: `release/1.0.0-figma-stable`. Tested source still has **0.1.0 Development** metadata; this report is not a Stable release certification. Native tests used isolated directories under `/tmp`, including `/tmp/urod-library-first-qa-20261026` and the E2E script's temporary directory. No real account, token, password, or user data directory was used.

Counts from the latest local runs: **19 frontend tests, 15 authentication tests, 37 app tests and 55 core tests passed** (126 total); **10 Rust tests were ignored** (1 authentication vault, 2 app live Ely.by, 4 core manual/live and 3 full game integration tests). The native process loop and UI probes above are additional checks, not counted as unit tests. The production build warned that the lazy skins JavaScript chunk is 531 kB; the build passed.

The 20-launch persistence scenario is repeatable with [`scripts/library-first-e2e.py`](../scripts/library-first-e2e.py). It builds its own temporary `urod-*` data directory, imports 15 PNG entries using one valid test texture, saves all 40 customization keys, applies three skins to each of three accounts, checks all data on each launch, force-kills the midpoint launch and removes the temporary directory afterward. On this host it completed 20/20 launches three times; the final run included all 40 settings. The separate Rust test imports 15 distinct PNG textures. Run a frontend dev server and a debug Tauri binary before invoking the script; its exact prerequisites are in [DEVELOPMENT.md](DEVELOPMENT.md).

## Defects fixed

1. The old Home page remained reachable and its nav link and logo target were still present. Home markup and startup routing were removed; legacy hashes now resolve to Library.
2. Renaming an offline account recomputed its UUID and broke account-bound skin selection. Rename now retains the UUID and rejects case-insensitive duplicate offline nicknames.
3. Skin selection history existed only as current `active_for` state. Native SQLite now records account UUID, skin ID or default-skin marker, saved name and application time, and the skin page exposes the last 100 events per account.
4. The frontend rejected the bundled Figma Inter/Geologica fonts as customization values. They are valid choices now. A single invalid saved value no longer discards other valid customization values.
5. Three controls that only changed the removed Home page were still visible. They were removed from the editor while their saved keys remain readable for older settings files.

## Limits and open work

- Microsoft and Ely.by real sign-in, Microsoft server-side skin verification with an authorized account, and Ely.by live skin retrieval remain untested. Mocks do not prove the live services.
- The new Vanilla install reused verified files already in the isolated QA cache. It did not test a clean network download under this branch.
- One forced app kill after completed writes passed. A kill during the narrow interval between skin index replacement and SQLite history insertion, power loss, and concurrent cross-process writes were not simulated.
- All 40 customization values passed frontend validation and persisted through 20 full launches; 37 are visible after removing Home. Every visible control was not individually exercised through the UI. The custom font variable is saved and applied, while Figma-specific components retain their prescribed Geologica/Inter typography.
- [CI run 40379304023](https://github.com/Yozekkk/urod-launcher/actions/runs/40379304023) passed verification and Windows, Debian and Arch package jobs on application commit `9073a1a`; packages retain 0.1.0 Development metadata. The reproducible E2E script and report updates were added after that run and tested locally.
- The debug Tauri process sampled about 381 MB RSS and its WebKit web process about 506 MB RSS while 15 skin previews were loaded. This is a point sample, not a leak test or production memory target. No performance or leak clearance is claimed.
- See [stable readiness audit](STABLE_1.0.0_AUDIT.md) for release blockers, disabled settings and installer coverage.
